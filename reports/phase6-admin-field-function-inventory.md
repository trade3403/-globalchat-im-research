# 壹信 V6 演示后台：功能与字段清单

- 整理日期：2026-11-27
- 对象：用户提供的 `imv6.66demo.cn` 管理后台演示（界面品牌显示“壹信V6集群”）
- 来源：本聊天中的登录后页面观察、装修工作台截图，以及 `phase6-competitor-feature-analysis.md`
- 用途：把可见功能、界面配置字段和反推的数据实体集中整理，供后续竞品分析与需求建模使用。
- 证据边界：字段清单分为“界面确认”和“数据模型推测”。后者是根据业务功能反推的建议字段，不是该产品真实数据库字段；目前未取得其 DDL、API schema 或数据库访问权限。

## 1. 结论摘要

演示后台覆盖 IM 关系链和消息运营、社交内容审核、会员钱包、AI 配置、客户端装修发布、安全审计及运维治理。产品功能总结已完成到后台模块/工作流层面。

在字段层面，现有证据能确认的是菜单、部分表单控件和配置项。例如装修工作台中的显示名称、导航图标、选中图标、导航顺序，以及 AI 模型配置中的 Base URL、模型名、密钥输入、超时、Token 上限、单价、月预算、默认供应商和内容审核开关。不能把这些直接描述成实际数据库列。

## 2. 模块功能与字段目录

“界面可见/文档明确”列只记录现有观察材料明确提到的控件或对象；“建议数据字段”列是后续设计/验证用的数据模型推测。

### 2.1 用户、认证与关系链

**功能**

- 用户管理、注册/登录规则和身份要求。
- 好友关系、好友验证、聊天搜索规则。
- 客服账号、专属邀请码和欢迎语。
- 设备、登录凭证、会话的运营管理入口。

**界面可见/文档明确**

- 注册规则、身份要求、手机号/邀请码等配置入口。
- 好友验证规则、搜索规则。
- 客服身份、专属邀请码、欢迎语。
- 用户和设备/登录凭证作为管理对象。

**建议数据字段（待 API/DDL 核验）**

| 候选实体 | 候选字段 |
|---|---|
| 用户 | user_id、用户名/昵称、手机号或外部身份标识、头像、账号状态、注册来源、注册时间、更新时间 |
| 设备会话 | session_id、user_id、device_id、设备类型、客户端版本、登录时间、过期时间、撤销时间 |
| 好友关系 | relation_id、申请人、接收人、关系状态、验证来源、申请时间、通过时间、备注 |
| 注册配置 | 配置版本、注册开关、身份校验方式、邀请码要求、更新时间、操作者 |
| 客服配置 | 客服 user_id、邀请码、欢迎语、启用状态、排序 |

### 2.2 私聊、群组、频道、消息与通话

- 消息记录、撤回记录、通话记录。
- 群/频道状态和官方标记。
- 成员上限、撤回时限等规则。

**建议数据字段（待 API/DDL 核验）**

| 候选实体 | 候选字段 |
|---|---|
| 会话 | conversation_id、conversation_type、成员/所有者 ID、会话状态、创建时间、更新时间 |

| 消息 | message_id、conversation_id、sender_id、消息类型、内容/内容引用、服务端序号、发送时间、撤回状态、撤回时间 |

## 3. 反推的共用字段约定（建议）

如果要基于这些业务域设计自己的 schema，可评估以下共用字段；它们不是从竞品数据库读取的：

- 主键：稳定 ID（如 user_id、message_id），避免用可变显示名作主键。
- 生命周期：created_at、updated_at、deleted_at 或明确的状态迁移记录。
- 审计：created_by、updated_by、operation_id、request_id。
- 多租户/多应用：tenant_id、app_id（仅在实际租户模型需要时）。
- 可追踪版本配置：config_version、发布状态、发布时间、发布者。
- 幂等与资金：idempotency_key、ledger_reference、reversal_of（只用于资金域并须按业务规则设计）。
- 内容/附件引用：使用受授权检查的 asset_id 或对象存储 key，不将长期公开 URL 当作授权凭证。

## 4. 字段可信度分级

| 等级 | 含义 | 例子 |
|---|---|---|
| A：截图/页面直接可见 | 控件标签、菜单名、当前预览值确实出现在 UI | “显示名称”“导航图标”“选中时图标”“导航顺序”“模型名”“Base URL” |
| B：报告明确记录的业务对象/配置 | 之前的后台页面记录或说明明确提到，但未逐字段抓取表格 | 充值审核、提现申请、举报处理、数据保留周期、最低客户端版本 |
| C：反推的候选 schema | 为后续需求建模按功能推导，需由真实 DDL/API 核验 | ledger_id、审核人、幂等键、发布记录字段 |
